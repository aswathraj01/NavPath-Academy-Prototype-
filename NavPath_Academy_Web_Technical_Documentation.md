# NavPath Academy — Django Web Application Technical Documentation

## 1. Architecture Overview

The NavPath Academy web application is a **full-stack Django monolith** connected to a **Supabase-hosted PostgreSQL** database. It serves the same maritime exam-prep product as the Flutter mobile app through a browser-based interface, with a fully functional backend, real database persistence, and a Django Admin panel for content management.

- **Framework**: Django 5.2.17
- **Language**: Python 3.12
- **Architecture Pattern**: MVT (Model–View–Template) — Django's standard pattern.
- **Database**: PostgreSQL hosted on Supabase (connection pooling via PgBouncer, port 5432).
- **Static Files**: WhiteNoise middleware (gzip-compressed, fingerprinted).
- **Deployment Target**: Render (WSGI via Gunicorn).

## 3. Django Apps

### `core`
Public-facing pages that require no login.

| Model | Purpose |
|-------|---------|
| `Notification` | Per-user notifications with type, read flag, and timestamp |
| `Message` | Internal user-to-user messaging (inbox/outbox) |

| `SupportTicket` | User-raised support requests with status tracking |
| `FAQ` | Publicly visible FAQ entries, ordered and categorised |

**Management Command**: `python manage.py seed_data` — populates the database with all course categories, courses, lessons, mock test questions, study materials, and sample FAQs for a fresh install.

### `enrollments`
Handles the enroll action and checkout page.

| Model | Purpose |
|-------|---------|
| `Enrollment` | Links a user to a course; tracks `progress_percentage` and `last_accessed` |

## 6. Settings & Environment

All secrets are loaded from `.env` via `django-environ`. **No secrets are hardcoded.**

| Variable | Purpose |
|----------|---------|
| `SECRET_KEY` | Django cryptographic key |
| `DEBUG` | `True` locally, `False` on Render |
| `DATABASE_URL` | Full PostgreSQL connection string (Supabase) |
| `ALLOWED_HOSTS` | Comma-separated list of valid hostnames |

**Production-only security settings** (auto-enabled when `DEBUG=False`):
- `SECURE_SSL_REDIRECT = True`
- `SECURE_HSTS_SECONDS = 31536000` (1 year, with subdomains + preload)
- `SESSION_COOKIE_SECURE = True`
- `CSRF_COOKIE_SECURE = True`
- `X_FRAME_OPTIONS = 'DENY'`

## 7. Deployment (Render)

Deployment is fully automated via [`render.yaml`](render.yaml) at the repo root.

**Build command** (runs on every deploy):
```bash
pip install -r requirements.txt
python manage.py collectstatic --noinput
python manage.py migrate --noinput
```

**Start command**:
```bash
gunicorn navpath_web.wsgi:application --bind 0.0.0.0:$PORT --workers 2 --timeout 120
```

Required **Render Dashboard environment variables**:

| Variable | Value |
|----------|-------|
| `SECRET_KEY` | Strong random key |
| `DATABASE_URL` | Supabase `postgresql://` URL |
| `ALLOWED_HOSTS` | `your-service.onrender.com` |
| `DEBUG` | `False` (pre-set in render.yaml) |

## 9. Testing

The project includes two test files (`Web/check_issues.py` and `Web/test_mock_e2e.py`) for manual/integration checks.

*Formal automated unit tests are not yet wired into Django's test runner. Below are the key proposed test cases.*

### Proposed Test Cases

1. **Enrollment is idempotent**
   - *Action*: `POST /enrollments/enroll/` twice with the same `course_id` for the same user.
   - *Expected*: Second request returns "already enrolled" message; only one `Enrollment` record exists.

2. **Lesson completion updates progress**
   - *Action*: `POST /courses/mark-complete/` with `lesson_id` and `course_id`.
   - *Expected*: `LessonCompletion` created; JSON response contains updated `progress` integer; `Enrollment.progress_percentage` updated in DB.

3. **Mock test scoring**
   - *Action*: `POST /courses/mock-tests/submit/` with all correct answers.
   - *Expected*: `MockTestResult` created with `score == total`; redirect to test results page showing 100%.

4. **Static files served in production**
   - *Action*: `GET /static/css/style.css` with `DEBUG=False`.
   - *Expected*: 200 response served by WhiteNoise (not Django's dev server).
